# Intent: [Short Title of Idea or Feature]

## 1. Problem

- **What does not work today:** Describe the current pain point, inefficiency, or missing capability in plain, ordinary language.
- **Who is affected:** Identify the specific users, roles, or internal systems struggling with this limitation.

## 2. Proposed Outcome

- **What "better" looks like:** Define the desired end state and the concrete value delivered once this intent is fulfilled.
- **Core success criteria:** High-level indicators that tell you the problem has been successfully solved.

## 3. Affected Users and Systems

- **User impact:** Which user groups will interact with or notice this change?
- **System impact:** Which services, codebases, repositories, or infrastructure components are touched or modified?

## 4. Constraints

- **What is off-limits:** Explicit boundaries, architectural limitations, tech stack restrictions, or out-of-scope items.
- **Compliance / Security / Policy:** Non-negotiable rules the solution must respect.

## 5. Open Questions

- **Unresolved aspects:** Known unknowns, product decisions, or technical ambiguities left to clarify during the subsequent specification (`spec.md`) phase.
